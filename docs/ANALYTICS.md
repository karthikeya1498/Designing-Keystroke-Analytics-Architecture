# Phase 3: Feature Extraction and Behavioral Model

## Input contract

The analytics engine consumes only `SanitizedKeystrokeEvent` records. It sorts events by timestamp and sequence number, counts `key_press` records, derives correction and backspace counts, and reads timing values already calculated by the local collector. It has no dependency on raw typed characters.

## Metrics

| Metric | Calculation |
|---|---|
| Character count | Character-like key codes from `key_press` events (`KeyA`, `Digit1`, `Space`, and normalized punctuation) |
| WPM | `characterCount / 5 / durationMinutes` |
| Error rate | `correctionCount / keyCount` |
| Accuracy | `1 - errorRate`, bounded to `[0, 1]` |
| Dwell statistics | Mean, median, and p95 of local keyup-minus-keydown durations |
| Inter-key statistics | Mean, median, and p95 of local keydown-minus-previous-keyup delays |
| Pause count | Inter-key intervals greater than or equal to two seconds |
| Fatigue score | Bounded deterministic heuristic from duration, error rate, pause count, and mean latency |

Empty distributions return `null` rather than zero so the dashboard can distinguish unavailable data from a measured zero. Percentiles use linear interpolation over sorted observations.

## Behavioral model pipeline

`BehavioralModelPipeline` owns one session and user identity, rejects events from other sessions, rejects duplicate sequence numbers, and exposes a snapshot generated by `extractBehavioralFeatures`. The current pipeline is intentionally deterministic and explainable. It is a feature-engineering layer, not a machine-learning classifier and not an authentication decision engine.

## Dashboard integration

The page stores sanitized events for the active browser session, builds a session-scoped pipeline, and passes its snapshot into `AnalyticsPanel`. The dashboard therefore presents observed WPM, accuracy, key count, mean dwell, mean inter-key latency, pause-aware fatigue, and an observed WPM chart. The old UI-only counters remain as a display fallback until the first sanitized event is available.

## Limitations

The browser sandbox cannot establish a long-lived per-user baseline yet, so the score is not a z-score and does not claim anomaly detection. That belongs to Phase 5. The fatigue score is a transparent behavioral signal only; it is not a medical assessment, identity proof, productivity judgment, or security verdict.
